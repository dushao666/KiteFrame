# 项目规则（KiteServer）

## 语言要求

- **必须始终使用中文回答用户的所有问题和消息**，包括解释说明、错误信息、提交信息（commit message）和 PR 描述等。
- **思考过程（thinking）也必须使用中文**。
- 代码中的标识符（变量名、类名、方法名等）按项目现有规范使用英文；注释、XML 文档说明、日志文案使用中文，与现有代码库保持一致。

## 开发规范（强制）

- 编写、修改任何代码之前，**必须先阅读并严格遵守 `docs/项目开发规范.md`**（项目根目录下的 `项目规范.md` 为同一份规范的副本）。
- 该规范涵盖：技术栈与编译约定（.NET 9 / Nullable / XML 文档）、分层架构与依赖方向（Api → Application → Domain / Repository / Infrastructure / Shared）、CQRS + MediatR 用法、SqlSugar 仓储、命名与代码风格、测试规范（第 14 章）等。
- 新增或修改代码时，以该规范为准；**规范未覆盖的情形，以现有代码库的实际写法为准，保持风格一致**。
- 如果发现现有代码与规范冲突，先向用户说明，不要擅自大规模重构。
- **编写/修改代码时，必须为新功能同步补充对应测试**（规范第 14 / 14.5 章）：新 Validator 必须有校验器测试；新增独立逻辑、工具方法、映射配置必须补单元测试；新 API 端点建议补集成测试。测试统一使用 xUnit，目录与命名镜像 src 的模块结构，提交前 `dotnet test` 必须全部通过。

## 工作流程

- 涉及多文件的改动前先制定计划；改动后必须运行 `dotnet build` 与 `dotnet test` 确认全部通过（测试位于 `tests/UnitTests`、`tests/IntegrationTests`）。
- 不确定的约定优先查阅 `docs/` 目录下的文档，其次参考同类现有代码的写法。
